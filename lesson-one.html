Lesson 1: Introduction to User Interface Design


User Interface Design is the planning and creation of a set of controls that enables a user to interact with a computer device

Goal: make the interaction between human user and computer device simple, effecient, effective, and enjoyable.

Intro to UI Design

6 principles of good UI design:

  • Structure: clearly understandable at a glance
    • site map with clear navigation
  • Simplicity: self-explanatory; easy to use; unadorned layouts, images, and colors
  • Visibility: easy on the eyes, legible text, each page has a clear purpose, straightforward, predictable, clear metaphors
  • Feedback: timeliness when an input is accepted, when an error has occured, when the site is still working
  • Tolerance: high level of tolerance minimize errors, easily undo or redo actions when an error does occur
  • Reuse: make aspects reusable to maintain consistency, reduce the need to rely on thought and memory

design trends:

  • Mobile Devices: designing for mobile is now the rule, must be able to work on all devices
  • Flat Design: simple navigation, plenty of white space, large and bold images and fonts, single color dominance
  • Data Visualization: depicting complex data in simple visual form
  • Scrolling Trends: Parallax scrolling (when background and foreground scroll at different rates depending on how fast the user is scrolling), long-page scrolling
  • Human look & feel: hand drawn elements, stories

Evolution of Web User Interfaces

MIT professor J.C.R. Licklider researched into a "Galactic Networ" in the 60s that would foster social interaction betwen users. In the early 60s, UCLA and a few other universities fostered the creation ofARPAnet, the Advanced Research Project Agency (ARPA) network. ARPAnet then fostered the creation of the Internet, which was officially born in 1982 with the standardiszation of the Transmission Control Protocol/Internet Protocol (TCP/IP), a suite of protocols for sending and receiving messages over the Internet.

In 1989, Tim Berners-Lee, a British computer scientist and employee of the European Organization for Nuclear Research (CERN), wrote a proposal for a more effective communication system for CERN, which he realized could be implemented globally. In 1990, he and a Robert Cailliau, a Belgian computer scientist, proposed the use of the hypertext "to link and access information of various kinds as a Web of nodes in which the user can browse at free will."

The World Wide Web was born: a system of interlinked hypertext documents that reside on the Internet and can be accessed via Web browsers.

Note:The Internet is a massive network of networks that connets millions of computers across the globe. The World Wide Web is a vast library of hypertext documents (Web pages) that are stored on the Internet and viewed in Web browsers

The first Web site

August 1991 Tim Berners-Lee published the first site for the World Wide Web

Early HTML elements

The earliest versions of Hypertext Markup Language (HTML) suported only a few basic Web site elements:

  • headings (<h1>,<h2>, etc.)
  • paragraphs (<p>)
  • links (<a>)

they were very s imple, single-comlumn, text only, standard fonts, underlined links. Later images (<img>) also came along.

Type-based layouts

HTML <table> element was created to display tabular, spreadsheet-like data. But designers realized that could be used to lay out their page content. Multi-column layout became common. Now, they are rarely used for layout, w. CSS3 being used instead.

Flash

tables began to be to complicated and bulky, so Macromedia, Inc. introduced Flash technology, which started in 1996. It enabled designers to overcome severe limitations of HTML. It became possible to create sites with interactive animations. But there were downsides:

  • it required the plug-in, which every user might not have, or have up-to-date
  • Flash-heavy pages took too long to load and often had confusing navigation.
  • Flash is a closed system, controlled by one company (now Adobe), vs standard Web languages, which are open-source technologies. Project developnent was hampered by slow responses to improving the software.
  • Flash amassed a history of weak security and for crashing Macs, which resulted in Apple's discontinued support of Flash on Apple products in 2010

Dynamic HTML (DHTML)

This was beginning to be used around the same time as Flash was emerging. DHTML is an umbrella term for a set of technologies used to create interactive Web sites, typically HTML, JavaScript, and CSS. With this and Flash, the notion of interactive webpages was introduced. However DHTML continues to be used because the technologies on which it's based are standard open-sourced technologies that do not require any special software or plug-ins to develop or use.

  • HTML5 (current version of HTML)
    Being so sophisticated, it was also responsible for the decline of Flash. It, with CSS and JavaScript can do anything Flash can well, or better.
  • Cascading Style Sheets (CSS) (current standard is CSS version 3 (css3))
    technology specifies the appearance of the HTML documents (web pages). It is very flexible and powerful, enabling a single page to lay out or design for a whole site.

You no longer can design for desktop, and tweak later for mobile. You need to think mobile from the beginning.

Responsive design is required

this is typically accomplished using fluid page grids, flexible images, and CSS3 media queries

Less is more

Flat UI objects, simple navigation,a dn plenty of white space are all desireable in current interfaces

large, bold images and fonts are currently in style.

Data visualization

depicting data in simple visual form

Parallax

Long-scrolling pages

Web Design Team Roles and Responsibilities

core roles of every Web design team:

  • Project Manager: team leader
    • sets realistic expectation and deadlines
    • facilitates communication among team members
    • resolves disputes and maintains morale
    • solves problems
    • ensures that the work and budget stay on track
  • Strategist: formulates the Web site development strategy
    • drafts a mission statement for the Web site
    • researches the needs and expectations of itended site users
    • sets short-term and long-term project goals
    • in smaller projects, the project manager often doubles as strategist
  • Content Specialist: the content of the website
    • research
    • analysis
    • organization
    • writing and editing
    • choosing the appropraite text, images, and multimedia to achieve the site's goals
    • most important part; often gets assigned to non-professionals, under teh assumption that anyone with an interest in words can write good Web copy
  • Usuability Expert: provides visitors with satisfying experience
    • tests the Web site throughout the development process with intended users
    • evaluates the site's usability against other, similar sites
    • ensures that the site is culturally appropriate and accessibe to those with special needs
  • Designer: the appearance of the Web site
    • page layout, color scheme, typography, images, etc.
    • creates UI sketches (often hand-drawn)
    • converts these sketches into wireframes (simple blueprint-like line drawings)
    • elaborates the wireframes into page mockups (graphics that are like screenshots of actual Web pages)
    • creates the site's graphic images, which can be extremely time-consuming
    • web designers and developers are like the two hemispheres of a single Web site-creation brain. The designer is the right hemisphere: creative, imaginative, and intuitive. The developer is the left hemisphere: logical, linear, and analytical
      • just as with brain hemipsheres, some overlap exsists between design and development. designers should be comfortable with programming concepts and practice, and developers should have a keen eye for page design
  • Developer: once the strategy, content, usuability and design are all in place, someone has to actually write the code for the Web site
    • programs the front-end UI (using client-side code, sucha s HTML, CSS, JavaScript, etc.)
    • programs the back-end application (using server-side code such as PHP, MySQL, etc.)
    • organization
    • tests, revisits, and re-tests multiple times, using multiple browsers, including mobile devices until everything on the site looks and behaves exactly as the project design dictates
  • Marketer: establishes a solid presence in the online world
    • goals
      • locate potential customers
      • reach out to them
      • bring them to the site
      • convert them into leads and sales
    • completes goals by strategically communicating through:
      • blogging
      • sending out group mailings
      • creating special offers
      • posting to social networking sites like Facebook, Twitter, YouTube, etc.
    • the do this effectively, the marketer must be able to create site-specific content, understand the lates Internet trends, and - above all - grab the interest of users in the intended audience

Web Design Project Management

the mantra of a project manager is: "On time and on budget."

their tasks include:

  • understand the "big pictue" of the projects
  • coordinate the activities and tasks
  • keep tasks aimed at the goal
  • keep project components on schedule and within the budget guidelines
  • maintain project documentation
  • facilitate communciation among all project team members
  • in larger projects, the project manager is rarely part of the hands-on production team, but in smaller projects, she might double as designer or developer

Project Phases

different teams sue differed models, but msot share these essential phases:

  1. information gathering: answer basic questions such as what does the customer want/need, what do the intended site users want/need, who are the main competitors, what can your Web site offer that theirs do not?
  2. planning: several components must be determined before the work can began, such as the site map, navigation system, Web technologies, work schedule, etc.
  3. design: color scheme, typography, layout, UI sketches and wireframes, mockups, and graphics creation
  4. development: building the site from a technological standpoint, including front-end and back-end coding (HTML, CSS, JavaScript, PHP, MySQL, etc.) and content entry (words, images, videos, and other multimedia)
  5. testing: sites should always be tested thoroughly to ensure that they will function as expected under as many variable conditions as possible. Consider the interative TAR process: test, assess, redesign - test, assess, redesign, etc.
  6. delivery and maintenance: along with delivering a finished site, you must ptovide additional support components and services, including customer support, site backups, adding/changing content, isntalling updated widgets and plug-ins, fixing broken links, and so forth

Project Documentation

also differs from team to team. the most common to Web design projects:

  • budget and billing spreadsheets: the detaisl involving money will dictate a project's scope, so it is essential for them to be organized and documented
  • work schedules: these include deliverables and deadlines for all tasks and team members
  • meeting notes: these documents keep everyone informed of the same details and working together
  • design document: the compendium of all the design-centered documentation generally includes goal statements, competitor analyses, customer interviews, functional specs, sketches, witeframes, mockups, and so forth
  • web site style guide: a collection of the stylistic conventions for a Web site, including page layouts, color schemes, typography, graphics, tone, content, page widgets, etc. A style guide promotes consistency in content and formatting. It is crucial for a large site that is expected to exist for a number of years and continue to be developed, perhaps by new design team members
